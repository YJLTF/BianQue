## 2. 阶段明细

### S0 工程奠基（第 1–2 周）

| 工作项 | 产出 |
|---|---|
| Monorepo 初始化（server/web/deploy/scripts 骨架） | 仓库 + 目录规范 + 代码规约（含 gitleaks、dependency-check 门禁） |
| CI/CD 流水线 | 构建→单测→Testcontainers 集成→镜像→靶场冒烟 |
| 本地/靶场环境 Compose | MySQL/Redis/MinIO/Nginx 一键起；math-game 靶场镜像（JDK 8/11/17/21）+ 3 类故障注入脚本 |
| 文档管线 v0 | 解包→manifest→索引脚本固化（manifest 已交付） |
| 安全基线设计评审 | `arthas.properties` 下发模板、端口绑定、黑白名单、审计表结构评审通过 |

**M0 门禁**：空平台可登录（SSO 假账号）；靶场容器可注入 CPU 故障并被脚本采集；CI 全绿。

### S1 公共底座 + P5/P6 MVP（第 3–6 周）

| 工作项 | 说明 |
|---|---|
| Agent 安装器与纳管 | 安装命令生成器（systemd / as-service.bat）、tunnel 注册、应用/实例台账、心跳在线率 |
| 执行引擎 v1 | `DiagExecutor` 双通道（batch-file/HTTP API）；超时、按主机限频、只读重试、熔断；结果结构化解析 |
| RBAC v1 + SSO | OIDC 登录、应用×命令族×角色五表、只读模式开关 |
| 审计中心 v1 | 全操作落库（含急诊/AI 来源标记）、哈希链、按实例/操作人检索 |
| **P5 档案 MVP** | 批量 `sc -d` 应急扫描（分批串行）、命中台账、导出 |
| **P6 体检 MVP** | 巡检模板（jvm/memory/thread/classloader/CPU）、阈值打分、健康分报表 |

**M1 门禁**：对 10+ 靶场实例完成一次档案扫描与全量巡检；健康分报表可导出；审计可完整还原上述操作。✔ 对应报告"第 1 个月见效"。

### S2 文档中心 v1 + P1 急诊（第 7–10 周）

| 工作项 | 说明 |
|---|---|
| 文档中心 v1 | `/docs/4.3.5/` 托管、双语目录（78 页）、全文搜索、风险徽标；L2 参数旁帮助锚点；L3 命令即文档侧栏 |
| Web 前端主体 | 应用/实例树、模板库框架、审计界面、文档中心界面（原型即验收蓝本） |
| **P1 急诊** | Webhook 接入（Prometheus/Grafana/Zabbix）；取证流水线（attach→thread→memory→profiler）；现场报告渲染（线程 TOP 分类/内存水位/火焰图/疑似结论）；企微推送；同进程限频；heapdump 审批+加密 |

**M2 门禁**：靶场注入 CPU 故障 → 告警 webhook → **≤60 秒**收到含疑似结论的报告（PRD 指标）；文档中心断网可用、搜索首条命中达标。

### S3 智能问诊 P2（第 11–14 周）

| 工作项 | 说明 |
|---|---|
| 个人版接入指引 | 零开发：内置 MCP 端点配置文档 + 一键复制（4.3.5 独有红利，优先发布引流） |
| MCP 网关 v1 | list_apps / pick_process / 工具转发；只读白名单强制；逐步审计；会话限流；高危动作转人工确认 |
| Playbook 引擎 v1 | YAML SOP：CPU 高 / OOM / 慢接口三条采集路径；工具调用时间线可视化、可中断 |

**M3 门禁**："为什么慢"一句话排障 demo 闭环：调用链全部只读、每步可查审计、高危注入被拦截（渗透用例）。

### S4 会诊 P3 Web 诊断台（第 15–20 周）

| 工作项 | 说明 |
|---|---|
| 表单化命令构建器 | watch/trace/tt/thread/profiler/dashboard/memory/ognl 表单 → 命令原文预览；高级参数渐进披露 |
| 会话托管 | 平台持有会话、30 分钟倒计时自动 reset+stop、高危二次确认弹层 |
| 结果可视化 | 线程池视图、trace 耗时树、tt 记录表格、火焰图交互组件 |
| 模板库 10+ | 慢接口/CPU 高/死锁/内存/日志级别/连接池等场景模板 + 团队共享与审核流 |

**M4 门禁**：未接触过 Arthas 的新人依模板**≤5 分钟**完成慢接口排查（PRD 验收指标）；会话结束后靶场验证无增强残留。

### S5 听诊 P4 + 加固交付（第 21–24 周）

| 工作项 | 说明 |
|---|---|

**M5 门禁**：产品设计方案 6.3 发布检查单五项全绿；离线环境全流程演练通过。✔ 对应报告"第 4–6 个月"。

## 3. 横切工作流（贯穿全程）

- **安全**：每阶段门禁含安全项；只读模式默认开；高危功能上线必须先有审批流。
- **测试**：靶场冒烟进 CI；每个里程碑跑一次 JDK 矩阵回归。
- **文档**：用户手册与功能同PR交付；操作视频随 M2/M4 录制。
- **度量**：按产品设计方案第 8 章指标，每里程碑出度量报告（易用/集成/安全/可靠四组）。

## 4. 里程碑与人力分配建议

| 阶段 | 后端 A | 后端 B | 前端 | 测试/SRE |
|---|---|---|---|---|
| S0 | 工程骨架/CI | 执行引擎 PoC（batch 通道打穿） | 前端骨架/登录 | 靶场+故障注入 |
| S1 | 纳管/台账 | 执行引擎/审计 | 表格与基础界面 | 兼容矩阵初测 |
| S2 | 急诊流水线 | webhook/限频 | 文档中心界面+搜索 | 端到端取证演练 |
| S3 | MCP 网关 | Playbook/LLM 适配 | 问诊界面/时间线 | 红队测试 v1 |
| S4 | 会话托管/命令通道 | 模板库/录制回放 | 表单构建器/可视化 | 可用性测试（新人 5 分钟） |
| S5 | 听诊/调度 | 性能基线/离线包 | 火焰图 diff | 渗透+矩阵终测 |

关键路径：执行引擎（S1）→ 急诊（S2）→ 会话托管（S4）；文档管线与前端界面可并行不阻塞关键路径。

## 5. 风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| tunnel-server 官方组件版本兼容 | 中 | bq-tunnel 锁定验证过的版本；升级走灰度靶场 |
| 存量系统 JDK 6–8 | 中高 | 发行包多版本并存（`--use-version`）；S5 矩阵实测；不可覆盖场景明确声明不支持 |
| attach 风暴/业务影响 | 高 | 限频+错峰+分批串行为默认；上线前压测基线；高危场景默认只读 |
| MCP 协议演进 | 中 | 网关适配层隔离，协议版本锚定 2025-06-18 |
| LLM 误操作 | 高 | 只读白名单、人工确认、沙箱靶场演练（S3 红队专项） |
| 4 人团队单点 | 中 | Playbook/文档沉淀；关键模块结对评审；里程碑可演示降依赖 |
| 审批流自研过重 | 低 | 起步用平台内置双人审批工单，不引外部 BPM |
