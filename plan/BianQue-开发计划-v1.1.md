## 0. 版本主题与取舍原则

一句话主题：**从"能诊断"到"会诊断"**——模板从硬编码变资产、结果从文本变图形、AI 从问答变会诊、参数从改配置文件变页面点选。

- **P0**：版本必须项，进发布门禁；**P1**：时间允许则做，不阻塞发布；**P2**：观察项，记录到 1.2 候选。
- 依赖决定阶段顺序（解析先于图表、配置中心先于阈值可配、markdown 先于 AI 会诊展示），与需求提出顺序无关。
- 不新增外部中间件依赖（无向量库 / 无消息队列），规模（78 页文档、单机部署语义）不支撑，详见 §6 风险。
- **2026-10-29 第一批已落地**（R1 提前完成大半，详见各节「已完成」标注）：诊断执行前端假超时修复、参数中心首批 7 项（含探针动态心跳跟随）、管理页「参数配置」区块、AI 回答 Markdown 渲染、诊断台执行结果一键「AI 分析」+ 转问诊台追问。

## 2. 工作项明细

### A0. 线上问题修复：诊断执行前端假超时（已完成 2026-10-29）

**现象**：线上执行诊断报 `timeout of 15000ms exceeded`——全局 axios 客户端 15s 超时，而服务端命令超时 60s（Agent 通道等待上限 90s），长命令必被前端先行中断，属前端假超时。

| 修复点 | 内容 |
|---|---|
| `executeDiag` | 单独超时 150s（覆盖命令超时可调上限 + 通道余量），注释写明与服务端参数中心的联动关系 |
| `attachLocalProcess` | 120s（arthas-boot attach 耗时波动大） |
| 急诊取证 `rescue` / 档案 `atlas/scan` | 各 300s（模板串行多条命令 / 批量 sc -d），同批排查发现 |
| 巡检 / LLM | 已有单独超时（150s / 300s），不动 |

**实测**：本地栈 + 拟真通道 `thread -n 5` 正常返回。配套闭环：参数中心命令超时上限收为 **120s**（Agent 通道等待 = 超时+30s ≤ 前端 150s 预算），杜绝"配置改大又复现假超时"。

## 5. 安全红线（v1.0 红线全部继承 + 新增）

- AI 可执行命令**全量过平台黑名单裁决**：内置基线（ognl/redefine/retransform/mc/groovy/heapdump）AI 发起直接拒绝，**不存在审批放行**；管理员可在页面追加加严项（见 §9），对人工与 AI 链路同口径；增强命令审批上限仅为 watch/trace/tt/monitor/stack/profiler/jfr。
- 工具调用步数、命令超时、产物大小上限**服务端强制**，前端仅是展示。
- `sys_config` 红线项（端口绑定/强制认证/审计开关/黑名单内置基线）不可配置、接口层拒绝写入；黑名单追加项为唯一例外——list 型参数、仅可加严方向。
- 每次配置变更、模板变更、AI 工具调用、审批决策入审计哈希链；LLM/embedding 密钥掩码不出平台。
- Markdown 渲染经 DOMPurify 消毒，与现有 CSP 一致；工件仅同源可访问（SAMEORIGIN）。

## 6. 风险与对策

| 风险 | 对策 |

| 火山图样本少、非严格统计 | 产品口径定位"参考性对比"（界面标注采样窗口数与检验方法），不宣称统计显著；样本不足自动降级表格 |

| profiler 产物过大 / 剖析拖垮目标 | 时长 ≤120s、产物 ≤20MB、增强命令限频沿用、审批卡人工放行 |
