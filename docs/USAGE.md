# 扁鹊 BianQue · 使用指南（v1.0.0）

> 面向平台使用者（运维 / 研发 / 只读方）。部署安装见 [`deploy/README.md`](../deploy/README.md)，
> 迭代变更见 [`CHANGELOG.md`](../CHANGELOG.md)。平台基于 Arthas 4.3.5，登录后左侧导航即十页功能流。

## 角色与权限

| 角色 | 账号（首次启动种子） | 能做 |
|---|---|---|
| ADMIN 管理员 | admin / admin123 | 全量：诊断执行 + 用户管理（新增/停用/重置密码/改角色）+ LLM 配置 + 连通测试 |
| OPERATOR 运维 | ops / ops123 | 诊断执行（命令/巡检/取证/扫描）+ 全部只读视图 |
| VIEWER 只读 | viewer / viewer123 | 仅浏览，写操作 403 |

- 登录签发 token（8h 滑动过期），所有 `/api/**` 强制认证；401 自动跳登录页
- 内置 admin 账号不可停用、不可改角色（防误操作锁死平台）
- 所有诊断动作写入审计哈希链（防篡改，审计中心可一键校验）

## 三个典型工作流

### ① 新节点接入 → 真实诊断（核心链路）

1. 目标主机装好 JDK 11+，按「节点管理」页三步指引下载 `bq-agent.jar`、放置 `arthas-boot.jar`、启动探针
   （或用 Docker/裸机 systemd 方式，见 [`deploy/README.md`](../deploy/README.md)）；
2. 探针 5s 心跳自动上线，本机 JVM 进程出现在「节点管理」展开列表；
3. 点进程行的「去诊断 →」跳转诊断台（实例已自动选中）；
4. 选命令（如 `thread -n 5`）执行——命令经平台命令单下发到节点，arthas attach 执行后回传；
   结果标注「Agent 通道 · 真实执行」；
5. 结束后会话自动回收（卸载增强，防 arthas 残留）。

### ② 慢接口 / CPU 飙高排查（诊断 + AI）

1. 诊断台用「慢接口排查」模板（`trace ... '#cost>100'`）或「CPU 飙高」（`thread -n 5`）取证；
2. 复制输出到「AI 问诊 → 附加诊断上下文」，提问（如"CPU 高的线程都在做什么"）；
3. AI 自动检索 Arthas 文档知识库辅助分析，回答下方「参考文档」可点击溯源到文档中心对应页；
4. 需要留证时到「急诊取证」生成现场报告（审计留痕）。

### ③ 例行巡检 + 外部告警接入

1. 「巡检体检」发起一轮体检：虚拟线程并行体检机队实例，得健康分与扣分项；
2. 外部告警系统（Zabbix/Prometheus Alertmanager 自定义 Webhook 等）配置推送到
   `POST /api/alerts/ingest`（头 `X-Alert-Token`，令牌在部署时用 `INGEST_TOKEN` 配置）；
3. 告警进入「急诊取证」活动列表，级别自动归一化为 严重/警告/提示 三级。

## AI 问诊配置（管理员）

「AI 问诊 → 模型接入」卡片（点击头部可折叠）：

- **服务地址**：任何 OpenAI Chat Completions 兼容端点（OpenAI / DeepSeek / GLM / Qwen / vLLM 内网网关），
  Base URL 不含 `/chat/completions` 尾巴；API Key 只回传掩码，落库存储；
- **思考强度**：推理模型（o 系 / DeepSeek-R1 类）选 minimal~high，自动按推理模型约束发参；
  普通模型选「关闭」；
- **文档知识库**：默认开启——提问自动检索文档中心 78 页官方文档，Top-4 命中注入提示词，
  寒暄类问题零命中零注入；回答下方展示命中引用；
- **连通测试**：保存后可一键测试（走真实端点一句话往返）；
- 部署时也可用环境变量预置：`LLM_BASE_URL` / `LLM_API_KEY`（见 `deploy/.env.example`）；
  内网无真实端点时可跑 `python scripts/dev-llm-mock.py` 起假端点演示。

## MCP 接入（AI 客户端直连 Arthas）

Arthas 4.3.5 原生 MCP Server：被 attach 的目标进程在本机 `http://<目标主机>:8563/mcp` 暴露
29 个诊断工具（Streamable HTTP + Bearer Token 认证），Claude Desktop / Cherry Studio / Cline 等
AI 客户端可直接调用。工具清单与配置见「文档中心 → Arthas MCP Server」。
注意：该端点在**目标进程所在主机**的本机回环可达性与认证策略由 arthas 侧管理（`arthas-properties`），
平台侧命令链路（命令单/审计）与其相互独立。

## 常见问题（FAQ）

| 现象 | 原因与处理 |
|---|---|
| 节点在线但 attach 失败 | 探针进程用户必须与目标 JVM 用户一致；进程可能已退出（等下一轮心跳刷新）；同一 JVM 只允许一个 arthas agent，先停掉旧 agent |
| 实例下拉里没有某个进程 | 心跳每 5s 上报进程清单，稍等刷新；离线实例不可选 |
| 执行诊断无结果/超时 | 会话 30 分钟超时自动回收，重新执行即自动重建；命令受高危黑名单与限次限频约束 |
| AI 问诊报"LLM 未配置" | 管理员在「AI 问诊」页填写端点/Key/模型名，或部署时预置 `LLM_BASE_URL`/`LLM_API_KEY` |
| AI 回答没带参考文档 | 问题与知识库零相关（正常降级为纯对话）；或 LLM 配置了与文档无关的自定义系统提示词 |
| 巡检某实例扣分"执行失败" | 弹性降级设计：单实例失败只扣分不拖垮整轮；查该实例通道状态 |
| 审计校验失败 | 审计记录被篡改（设计行为）；立即排查数据库访问 |
| Windows curl 发中文 400 | 控制台 GBK 编码所致，测试时用 UTF-8 文件体；页面操作不受影响 |
